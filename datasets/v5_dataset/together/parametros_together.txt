DATASET
-------
  Train:  986 conversaciones  (~5,057,000 tokens)
  Eval:   109 conversaciones  (~561,000 tokens)
  Total:  1,095 conversaciones (~5,618,000 tokens)

  Formato:       JSONL (messages array)
  Roles usados:  system, user, assistant, tool
  Max tokens/conv: ~6,400 (p95: ~5,900)
  System prompt:   ~4,000 tokens (incluye personalidad + tools)


MODELO BASE
-----------
  Recomendado:  Qwen/Qwen3-14B
  Alternativas: Qwen/Qwen2.5-14B-Instruct
                Qwen/Qwen3-8B (más barato, menos capacidad)

  NOTA: Verificar disponibilidad exacta en:
  https://docs.together.ai/docs/fine-tuning-models


CONFIGURACIÓN RECOMENDADA (LoRA)
--------------------------------
  training_type:    LoRA (lora=True)
  n_epochs:         3
  learning_rate:    1e-5
  batch_size:       "max" (Together auto-selecciona)
  warmup_ratio:     0.1
  train_on_inputs:  "auto" (enmascara system+user, entrena solo assistant)
  n_checkpoints:    3 (para poder comparar épocas)
  n_evals:          5 (evaluar 5 veces durante el entrenamiento)

  NOTA: Together AI maneja lora_rank y lora_alpha internamente.
  No se exponen en la API. Los defaults de Together son adecuados
  para datasets de este tamaño (~1K conversaciones).


CÓDIGO PYTHON PARA LANZAR EL JOB
----------------------------------

  from together import Together
  client = Together()

  # 1. Subir archivos
  train_file = client.files.upload(
      file=open("together_train.jsonl", "rb"),
      purpose="fine-tune"
  )
  eval_file = client.files.upload(
      file=open("together_eval.jsonl", "rb"),
      purpose="fine-tune"
  )

  # 2. Crear job de fine-tuning
  job = client.fine_tuning.create(
      model="Qwen/Qwen3-14B",
      training_file=train_file.id,
      validation_file=eval_file.id,
      n_epochs=3,
      learning_rate=1e-5,
      batch_size="max",
      warmup_ratio=0.1,
      train_on_inputs="auto",
      n_checkpoints=3,
      n_evals=5,
      lora=True,
      suffix="mariana-v5",
      wandb_api_key="<TU_WANDB_KEY>",  # Opcional
  )

  print(f"Job ID: {job.id}")
  print(f"Status: {job.status}")

  # 3. Monitorear progreso
  status = client.fine_tuning.retrieve(job.id)
  print(status)

  # 4. Listar checkpoints cuando termine
  events = client.fine_tuning.list_events(job.id)
  for e in events.data:
      print(e)

CONSIDERACIONES PARA TOOL CALLING
-----------------------------------
  1. El dataset incluye tool calling en formato Qwen nativo:
     - assistant usa <tool_call>{"name": "...", "arguments": {...}}</tool_call>
     - tool responses usan role: "tool" con <tool_response>...</tool_response>

  2. El system prompt incluye el bloque <tools> con las 11 herramientas.

  3. train_on_inputs="auto" es clave: el modelo solo aprende de los
     mensajes de assistant (no memoriza user ni tool_responses).

  4. Si Together AI no soporta role "tool" directamente, convertir a
     role "user" con prefijo "[Tool Response]:" antes de subir.


EVALUACIÓN POST-ENTRENAMIENTO
-------------------------------
  1. Usar el eval set (109 conversaciones) para calcular loss
  2. Verificar manualmente 10-15 conversaciones de prueba:
     - ¿Se presenta como Mariana? ✓
     - ¿Pregunta nombre del cliente? ✓
     - ¿Usa herramientas correctamente? ✓
     - ¿No inventa precios? ✓
     - ¿Cierra con CTA? ✓
     - ¿No ofrece cotización por email? ✓
     - ¿Pregunta antes de buscar en inventario? ✓
  3. Comparar checkpoints de época 2 vs 3 (a veces época 2 generaliza mejor)


RECOMENDACIONES ADICIONALES
-----------------------------
  - Si el loss de eval sube después de época 2, usar checkpoint de época 2
  - Si el modelo repite frases textuales del training, reducir a 2 épocas
  - Si no sigue las instrucciones del system prompt, probar learning_rate 5e-5
  - Monitorear con W&B: train_loss, eval_loss, gradient_norm
  - Después de fine-tuning, probar en producción con 10 conversaciones
    reales antes de habilitar para todos los usuarios
